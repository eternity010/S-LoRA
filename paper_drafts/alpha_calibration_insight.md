# 论文素材：$\alpha$ 参数的物理量纲与硬件级校准

> **适用章节**: Section 4.2.1 "负载估算的物理量纲与硬件级校准"
> **状态**: 待整合进论文初稿
> **日期**: 2026-03-04

---

## 背景

在多租户大模型推理系统中，精确评估 Worker 的实时负载是实现高效路由的前提。传统的负载度量（如队列请求数或单纯的 Token 总数）忽略了 LLM 推理中 Prefill（预填充）与 Decode（解码）两个阶段在计算特性上的本质差异。为此，本系统在 RWPT (Rank-Weighted Pending Tokens) 公式中引入了关键的跨阶段校准参数 $\alpha$。

---

## 1. 物理量纲的重构与理论剖析

在系统早期的经验设计中，$\alpha$ 曾被误估为 $[0.05, 0.3]$ 区间内的超参数。然而，深入分析 Roofline 模型后发现，这种假设在物理量纲上是完全错位的。

$\alpha$ 的物理意义并非简单的"阶段时间比"，而是"单个 Decode 序列的推进耗时，等价于多少个 Prefill Token 的计算负载"。其数学定义为：

$$\alpha = \frac{T_{decode\_per\_step}}{T_{prefill\_per\_token}}$$

从底层硬件执行逻辑来看：

- **Prefill 阶段 (Compute-bound)**：主要依赖高度优化的稠密矩阵乘法（GEMM），能够充分压榨 GPU 的并发算力。
- **Decode 阶段 (Memory-bound)**：属于典型的访存密集型操作，每次生成单个 Token 都需要遍历并加载庞大的权重矩阵和完整的 KV Cache，算力利用率极低。

---

## 2. 硬件实测与极端数值的合理性验证

为了获取精准的 $\alpha$ 值，我们在 Worker 节点初始化阶段引入了轻量级的动态 Micro-benchmark。

以 LLaMA-7B 模型在单张 RTX 3090 (24GB) 上的实测数据为例：

系统在真实推理引擎（包含 PagedAttention 和内存池分配开销）下测得，处理单个 Prefill Token 的极细粒度耗时约为 $0.1 \sim 0.2$ ms，而执行一次包含完整上下文读取的 Decode 步骤耗时约为 $10 \sim 20$ ms。

将上述硬件基准数据代入公式，计算得出真实的 $\alpha$ 值稳定在 $80 \sim 100$ 之间（实测典型值为 $90.89$）。

**本环境实测数据（RTX 3090 × 3 + LLaMA-7B, d=4096）**：

| Worker | GPU | $\alpha$ |
|--------|-----|----------|
| Worker 0 | GPU-1 | 90.89 |
| Worker 1 | GPU-2 | 97.09 |
| Worker 2 | GPU-3 | 82.90 |
| **中位数** | — | **90.89** |

这一远超直觉的数值揭示了一个关键的系统性事实：在当前的显存带宽与算力配比下，Worker 执行一次 Decode 序列的计算代价，在时间维度上等同于处理近 100 个 Prefill Token。

---

## 3. 动态校准对防止队头阻塞（HOL）的决定性影响

$\alpha$ 参数的精准定标对全局路由决策具有决定性影响。

在消融实验中我们观察到，若采用朴素的 Token 计数模式或使用错误的低估 $\alpha$ 值（如回退至 $0.1$），路由器在感知负载时将出现严重的"视觉盲区"——它会认为正在执行大批量 Decode 任务的 Worker 负载极低，从而将大量新的长文本请求持续路由至该节点，引发严重的队头阻塞（Head-of-Line Blocking）和尾部延迟（Tail Latency）飙升。

相反，当系统采用动态实测的 $\alpha \approx 90$ 时，RWPT 模型能够精准捕捉隐性的显存带宽瓶颈。若某 Worker 正在并行处理 10 个 Decode 序列，其上报的惩罚项将达到约 900 个等效 Token 负载。全局路由器据此能极其敏锐地将新到达的突发流量（Burst Traffic）避开该节点，分流至处于空闲或处于 Prefill 阶段的 Worker 上，从而在多维异构负载下实现近乎完美的全局均衡。

这段素材在论文中的价值：

1. **体现 Systems 论文最看重的 "Insight"**：不仅提出了一个公式，而且解释了公式背后的计算机体系结构原理（Compute-bound vs Memory-bound）。
